# Баннеры нововведений

Миграция `0042_release_announcements.sql` запускает все текущие баннеры
одновременно на 7 суток с момента выкладки и делает их постоянными для
раздела «Информация». Содержимое, аудитория и подтверждения сохраняются.
На первой production-выкладке таблицы баннеров ещё нет, поэтому все
пользователи получат первый автопоказ; после «Понятно» повторов не будет.

Содержимое первой кампании, её постоянный ID и обе даты находятся в
`drizzle/0028_announcements.sql`, в одном `INSERT` в конце файла.
Начало: **19.10.2026 00:00:00 МСК**. Конец (не включается):
**26.10.2026 00:00:00 МСК**. Это ровно 168 часов для всех `clientId`.

Новые баннеры можно создавать в разделе «Баннеры» админки. Миграции с
`INSERT` также поддерживаются; применённые миграции не редактируют.
ID кампании повторно не используют. Содержимое хранится в `pages`.

Миграция `0041_announcement_lifecycle.sql` добавляет `permanent`: для всех
существующих записей — `true`, для новых по умолчанию — `false`. Остальные
данные и подтверждения не меняются. `starts_at` и `ends_at` допускают NULL:
пустое начало означает доступность сразу, пустое окончание — отсутствие срока.
Окончание остаётся абсолютной датой, не включается в интервал и должно быть
позже заданного начала. Время проверяется по часам PostgreSQL.

`GET /api/announcements` выдаёт начавшиеся непрочитанные кампании до окончания
автопоказа. `GET /api/announcements?information=1` выдаёт только начавшиеся
постоянные кампании, включая прочитанные и истёкшие. Исключения аудитории
действуют в обоих режимах. До старта кампания недоступна в обоих режимах.
Истёкшие временные кампании исключаются из активной выдачи; физического
удаления содержимого нет ни в API, ни в планировщике.

`POST /api/announcements` принимает только `id`; личность определяется сервером
по cookie. Подтверждения хранятся в `announcement_receipts` по паре
`(client_id, banner_id)`. Новый браузер может получить другой `clientId`:
сквозной авторизации в проекте нет. Сборка/перезапуск приложения не засеивают
кампании заново.

Баннер открывается на главном экране прогулок после проверки сессии и только
при сохранённом ЖК. При первом визите приветствие, выбор ЖК и подтверждение
«Район выбран» проходят без баннера; показ начинается через 3 секунды после
перехода на главную. При повторном визите с сохранённым ЖК действует та же
задержка: 3 секунды после открытия главной и восстановления сессии. Уход с
главной отменяет таймер; при возвращении отсчёт начинается заново.

Автоматически открытый баннер с окончанием закрывается по оставшемуся серверному сроку. Часы браузера
не используются для проверки активности: таймер отсчитывается через
`performance.now()` с учётом времени запроса. Подтверждение сохраняется только
по «Понятно» на последней странице; при ошибке кнопка позволяет повторить.


## Карусель и локальный просмотр

Слайды показываются в крупной карточке. «Далее», точки под карточкой и
горизонтальный свайп переключают слайды без автоматического или циклического
перелистывания. В карточке нет прокрутки: отступы адаптируются к экрану, а содержимое
при необходимости пропорционально уменьшается до доступной высоты. Точки и
завершающая кнопка остаются снаружи. Tab переводит фокус на точки и
на кнопку; Enter/Space активируют кнопки. Анимация переключения отсутствует,
в том числе при reduced-motion.

Кнопка «Информация» доступна в меню без флага окружения. Ручной просмотр
каждый раз открывает постоянные кампании с первого слайда, без ограничения
сроком автопоказа. Крестик справа сверху и Escape закрывают только ручной
просмотр, возвращая фокус на кнопку открытия. Автоматический показ крестика
не имеет. «Понятно» на последней странице сохраняет обычное подтверждение;
крестик подтверждение не сохраняет.

Старый диагностический API `?preview=1` сохраняет локальные ограничения
`ANNOUNCEMENT_PREVIEW` и не используется кнопкой «Информация».

## Несколько активных баннеров

Кампания `walk-places-2026-10` добавляется миграцией
`0037_walk_places_announcement.sql` на 7 дней с момента применения. Внизу
после миграции `0038_walk_places_announcement_menu.sql` показан общий с меню
пункт `MyPlacesMenuRow` (`places-help`), в баннере — без интерактивности.
Текст объясняет оба перехода: по ссылке «здесь» в окне выбора места или через меню.

Кампания `shared-pet-2026-10` добавляется миграцией
`0035_shared_pet_announcement.sql` на 7 дней с момента применения. Она объясняет
добавление общего питомца по QR-коду. Пример `pet-share` повторяет пункт
«Поделиться питомцем» из паспорта питомца, без интерактивности.

Кампания `site-share-2026-10` добавляется миграцией
`drizzle/0031_site_share_announcement.sql` на 7 дней с момента её применения.
Слайд рассказывает, как поделиться сайтом с друзьями. Внизу показан статичный
образец пункта «Поделиться сайтом» с иконкой и разделителями сверху и снизу
(`example: "site-share"`), оформленный как в меню настроек.
Миграция `0032_site_share_menu_icon.sql` заменяет название раздела в тексте
на маркер `{{menu}}`, который отображается как встроенная иконка меню.

Все активные непрочитанные кампании показываются в одной карусели: сначала
все страницы первой кампании, затем страницы следующей, в порядке API
(`starts_at`, затем `id`). Точки считают общее число страниц. «Понятно»
появляется только на последней странице и подтверждает всю подборку.
Если сохранение части подтверждений не удалось, повторная попытка отправляет
только несохранённые. Истечение срока одной кампании убирает только её
страницы; остальные остаются в карусели.

Новая кампания `telegram-notifications-2026-10` добавляется миграцией
`drizzle/0029_telegram_announcement.sql`. Её срок — ровно 7 дней с момента
однократного применения миграции. Слайд объясняет подключение уведомлений
через Telegram и содержит статичную копию нижнего меню: без ссылок,
обработчиков, фокуса, подсказок и анимаций. Пример `telegram-dock` использует
иконки и CSS существующего меню. Миграцию применяют существующим механизмом;
перезапуск приложения не продлевает кампанию.

## Управление в админке

Раздел «Баннеры» в `/dogsfather` показывает запланированные, действующие
и завершённые кампании. Создание позволяет задать заголовок, текст,
постоянность и обе даты; редактирование — постоянность и обе даты.
Все поля и отображаемые даты используют Москву (UTC+3), независимо от зоны
браузера. Сроки хранятся как абсолютные `timestamptz`.

«Запустить сейчас» записывает текущее время PostgreSQL в `starts_at`.
Окончание и подтверждения не меняются: прочитанный баннер не появляется
автоматически повторно. Истёкший баннер нельзя запустить без исправления
окончания. Перенос начала в будущее снова скрывает кампанию в обоих режимах.
Клиентская проверка автопоказа сохраняет прежний интервал 60 секунд.

Миграция `0033_announcement_exclusions.sql` добавляет `exclusions` с пустыми
массивами по умолчанию: `cities` — названия городов, `districts` — пары
`{city, district}`, `complexes` — тройки `{city, district, complex}`.
Любое совпадение запрещает выдачу, в том числе ручной просмотр и подтверждение.
Неизвестная география с исключениями не совпадает. Родительские исключения
действуют на всех потомков. Переименование и удаление локаций синхронизирует
исключения в той же транзакции.

`GET /api/dogsfather/announcements` возвращает все кампании и справочник
географии. `POST` создаёт баннер с заголовком, текстом и настройками показа.
`PATCH` принимает `id`: `schedule` сохраняет постоянность и обе даты,
`start-now` запускает показ, `action: "exclusions"` меняет `exclusions`, а
`action: "extend"` с положительным целым числом `days`. Обе операции защищены
существующей серверной авторизацией администратора; изменения проверяют origin.
Исключения проверяются по реальным составным ключам справочника. Продление
атомарно прибавляет к актуальному `ends_at` указанное число суток по 24 часа,
не меняя начало, содержимое и аудиторию. Дата должна оставаться в пределах
`9999-12-31T23:59:59.999Z`, поддерживаемых существующими потребителями дат.

Интеграционные проверки используют только отдельную временную схему БД,
переданной в `ANNOUNCEMENTS_TEST_DATABASE_URL`; схема удаляется после теста.
